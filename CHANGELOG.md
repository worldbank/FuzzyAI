# Changelog

## 0.2.0

The 0.1.0 public API (names, signatures, defaults, output columns, saved files, checkpoint stage names) keeps working. New behaviour is opt-in; the only behaviour changes are the four listed below.

### Added

- Staged, pluggable engine in `deduplix.engine`: normalize, block, compare, score, route, validate, cluster, consolidate. Every stage is swappable by name in YAML, by a registered function or by a Python object.
- New top-level exports: `Pipeline`, `PipelineResult`, `register`, `load_pipeline`, `EngineMatcher`.
- `Pipeline.default()`, `Pipeline.from_config(path_or_dict)`, `Pipeline.dedupe(...)`, `Pipeline.link(...)`, `Pipeline.to_config()`; `PipelineResult` with `matches`, `review`, `clusters`, `explain`, `save` and `to_legacy`.
- Component registry with `register`, `build`, `list_components` and entry-point discovery (groups `deduplix.<kind>s`).
- Pydantic config models and `config_json_schema()`; `${ENV}` interpolation in YAML.
- Normalizers (including `name_parser` for legal forms and fund designators), blockers (exact, token index, TF-IDF, phonetic, MinHash, embedding, brute force), comparators, scorers (weighted, feature, grade table, Fellegi-Sunter, model), threshold and rule routers.
- LLM layer split into provider (OpenAI, Anthropic, Databricks, callable, fake), prompt template, output parser and decision policy, with a response cache.
- Clustering (connected components, size-guarded, Louvain) and consolidation components.
- Evaluation helpers: pair, band and cluster metrics, synthetic data, silver-label building, and `train_scorer` for distilling labels into a GBDT scorer.
- `EngineMatcher`, a drop-in `Matcher` for `DeduplicationPipeline` backed by an engine pipeline.
- Optional extras: `blocking`, `phonetic`, `minhash`, `embeddings`, `normalize`, `llm`, `eval`, `all`.
- `fuzzy-ai` as a second console-script name for the same CLI as `deduplix`.
- mkdocs-material documentation under `docs/`, with the config reference and component catalogue generated by `scripts/gen_docs.py`.
- Module docstrings distinguishing `deduplix.validators` (pair validators) from `deduplix.validation` (input checks).

### Fixed

- Legacy `LLMValidator`: failed batches, missing fields and missing decisions still default to duplicate (unchanged), but now log a warning with counts. The new engine validator leaves such pairs `unvalidated` by default.
- Anthropic `max_tokens` was fixed at 1000 and truncated batches that include reasons; it is now a parameter with default 4096.
- Per-pair DataFrame filtering for metadata replaced by one id index per call.
- `iterrows` loops in `matchers.py`, `core.py` and `validators.py` vectorised.
- `remove_duplicates` no longer filters the whole frame per entity; it maps ids to first and last row positions once.
- Silent `ImportError` fallback for `utils` removed, so real import errors surface.
- `FuzzyMatcher.find_matches` documents that `additional_columns` is ignored; `EngineMatcher` routes extra columns to comparators.
- `validation/schemas.py` moved from pydantic v1 `validator`/`root_validator` to `field_validator` and `model_validator`.
- Packaging: pydantic and openai pins corrected, an anthropic extra added, README install name and URLs match the distribution (`deduplix`, `worldbank/FuzzyAI`).

### Behaviour changes

- The data hash used for checkpoints now includes the name column, so edited data no longer resumes a stale checkpoint. Checkpoints written by 0.1 do not resume once; rerun from scratch.
- `FuzzyMatcher` `n_workers` defaults to 4 (was 1), as documented in the README. Results do not change, only speed.
- `get_group` on a singleton returns only the entity itself.
- Invalid input raises `DataValidationError` instead of a bare `ValueError`. It is a subclass of `ValueError`, so existing `except ValueError` blocks still work.

### Removed

- The stray duplicate `deduplix/consolidation (1).py`, which was imported nowhere.
